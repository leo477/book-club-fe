### P2 request counts

Per journey on the mock, `/analytics/event` excluded, post-login `/events` stub on Next (so Next numbers stop at the hard navigation; Angular continues in the SPA and loads its shell).

| Journey | Next | Angular |
| --- | --- | --- |
| Guest loads `/login` | `session-status` x1 | `session-status` x1 |
| Guest login (load + submit) | `session-status` x1, `login` x1, then 1 document request `/events` | `session-status` x1, `login` x1, then in-SPA `/events` bootstrap: `clubs/my`, `config/maps-key`, `events/my`, `events?skip=0&limit=50`, `users/me/stats` (x1 each) |
| Guest register (load + submit + wait) | `session-status` x1, `register` x1, 1 document request `/events` | same as login plus `register` x1 |
| OAuth callback with a valid code | `session-status` x1, `exchange` x1, `/auth/me` x1, 1 document request `/events` | `session-status` x1, `exchange` x1, `/auth/me` x1, then the SPA `/events` bootstrap |
| **Refresh churn: 5 consecutive hard loads of `/login` with a live session** | `session-status` x5, **`/auth/refresh` x0**, `/auth/me` x5 | `session-status` x5, **`/auth/refresh` x5**, `/auth/me` x5, plus `config/maps-key` x5 and `users/me/stats` x5 |

Answer to the refresh-churn question: on Next a hard navigation costs session-status + me and **never rotates the refresh token**; the legacy Angular bootstrap rotates once per hard load (5 loads = 5 `POST /auth/refresh {}`). While `/events` and the rest of the authed app are still Angular, every Next to Angular hard navigation therefore costs exactly one refresh rotation (and each Angular-to-Next one none). That is what the plan accepted; the rate limit on `/auth/refresh` was **not** measured (mock, no real backend). The security agent's scripted journey on a real backend remains the source for that.

## Defects and deltas

| ID | Severity | Finding |
| --- | --- | --- |
| D-1 | **medium** (functional, user-visible) | **The OAuth failure message is lost on Next.** `oauth-callback.tsx` calls `showToast('error', ...)` and then `hardNavigate('/login')`; the reload drops the in-memory toast, so a user whose Google sign-in failed (or who opened `/auth/callback` without a code) lands on `/login` with **no message at all**. Verified: with a failed exchange the `oauth_failed` text is not visible within 3 s on `/login` on Next (uk and en), while on Angular it is visible (SPA navigation keeps the toast). The plan says "error -> /login with the message". Fix options: pass a marker (`/login?error=oauth_failed`, read once, then `history.replaceState`) or `sessionStorage` flash key holding a message key only (never a token). Same class as R8 D-5. Covered by two `test.fail` tests in `r9-auth.spec.ts` (they will start failing, i.e. flag themselves, once the message survives; remove the `test.fail` line then). |
| D-2 | **medium** (a11y/visual) | **Colour contrast on Next auth pages** (Angular has none). (a) Dark theme: the Google button text (`text-gray-700` forced, `#364153`) sits on the dark outline-variant background `#2d1f0e`: 1.55:1 and visibly unreadable in `next-login-375-dark.png`; (b) light theme: the footer link (`text-primary-600` `#9f6509` on the card `#f5eed8`): 4.17:1. Related visual delta: Next's card turns dark in dark mode while Angular's stays cream, so the white/gray text tokens of the card are chosen for a dark card; decide whether the dark card is intended. Asserted by `PARITY_STRICT_CONTRAST=1`. |
| D-3 | low | The callback page runs `GET /auth/session-status` before the exchange although it never uses the result (one extra request per callback; harmless but wasted, `useSession` in the provider tree). |
| D-4 | low (unverified in production) | **Text typed before hydration is lost.** React Hook Form's `register` ref callback writes the default value into the DOM input when it attaches, so characters typed into `#login-email` before hydration are wiped (the password typed after hydration survived). Reproduced deterministically on `next dev` (slow hydration) by `e2e/ui/public-pages.spec.ts` "wrong credentials" (it fills immediately) and by the first run of this spec. A production build hydrates much faster, so the window is small, but slow devices/networks hit it. Could not be re-checked on a production build (see Method). Possible fix: set `defaultValue`-preserving behaviour (`shouldUnregister` is not it) or disable the inputs until hydrated. My spec waits for hydration (`__reactProps$` on the form) so it is not a test flake source. |
| D-5 | info (delta) | Angular login/register navigate to `/events` with the router (SPA) after the book animation; Next hard-navigates (login immediately, register after a 1.5 s welcome card). Both end on `/events`. Next has no book intro. |
| D-6 | info (delta) | Angular `register` shows "Minimum 8 characters" for a too-short **display name** (template passes `requiredLength: 8`, rule is 2); Next shows the correct 2. The spec only asserts `Мінімум \d+ символів`. Improvement on Next. |
| D-7 | info | Angular keeps the access token in memory and reads tokens from login/register/refresh/exchange bodies; Next never does. No token-like storage on either. |
| D-8 | info | Google start URL on both: `<oauth base>/auth/oauth/google?origin=<encoded location.origin>`, exactly one query parameter. Host differs only because `NEXT_PUBLIC_OAUTH_BASE_URL` was set to a dummy host here; Angular's deployed value is `book-club-be.onrender.com/api/v1`. The real value for the Next preview/prod must be verified by devops. |

No non-test source in `apps/web` or `src/` was modified.
