# Security review: R7 events (feat/SCRUM-39-web-events)

Scope: apps/web events feed/detail/map, RequireAuth/RequireRole, CSP + Trusted Types Report-Only change (7ccfe60), `GET /config/maps-key` consumer. Backend read for reference only (book-club-be working tree).

## Findings

| # | Severity | Area | Finding | Status |
|---|---|---|---|---|
| F1 | Medium | Maps key (ops) | `GET /api/v1/config/maps-key` returns `MAPS_API_KEY` to any anonymous caller (5/min/IP). A browser Maps JS key is public by design, but its safety rests entirely on the Google Cloud HTTP-referrer restriction plus an API allowlist. The backend has a separate `MAPS_SERVER_API_KEY`, so the key served here must be the browser-restricted one and must never be the server key. Nothing in the repo can verify the restriction. Referrers must now include the Next origin(s) (prod domain, `*.vercel.app` preview pattern kept as narrow as possible). | **Owner action**: confirm in GCP |
| F2 | Medium | BE authz | `POST /events/{id}/attend` (`attend_event_service`) checks event status and the 3-day window only; it does not call `can_view_club`, whereas `GET /events/{id}` returns 404 for events of private clubs. A signed-in user who knows a private club event UUID can RSVP and probe existence (404 vs 400/201), and be listed as attendee. Needs the UUID, so link-holder only. Same family as R6 F1. | BE fix needed (reuse `can_view_club` in attend/cancel) |
| F3 | Low | CSP | `trusted-types` allowlist in the Report-Only header lists `lit-html`, `dompurify-internal`, `google-maps-api#html`, plus `default` and `'allow-duplicates'`. A `default` policy name in the list is harmless in Report-Only, but if enforced and a `default` policy is created by the Maps loader it would silently pass strings through as `TrustedHTML` (no real sinking protection). Re-evaluate the list from collected reports before enforcing. `script-src` has `https://maps.googleapis.com` but `strict-dynamic` makes host sources ignored in CSP3 browsers, the nonce'd loader propagates trust; the host is only a fallback for old browsers. Acceptable. | Accepted while Report-Only |
| F4 | Low | CSP | `img-src` allows `https://*.supabase.co` (any project, not just ours) and `connect-src` allows `data:`. Both widen exfil/inject surface slightly. Prefer the exact `<project>.supabase.co` host and drop `data:` from `connect-src` if Maps does not need it. | Recommend tightening |
| F5 | Low | CSP | `style-src 'unsafe-inline'` remains (Maps injects inline styles). No script impact. | Accepted |
| F6 | Low | Defence in depth | CSRF middleware only triggers when an `access_token` cookie is present. RSVP/join paths themselves are covered. | No action for R7 |

## Checks

1. **CSP / Trusted Types (7ccfe60)**: nonce + `strict-dynamic`; `worker-src 'self' blob:` (Maps vector tiles use blob workers; no `script-src blob:` needed); `img-src` and `connect-src` list only `maps.googleapis.com`, `maps.gstatic.com`, `www.gstatic.com` for Google. `frame-ancestors 'none'`, `base-uri 'self'`, `form-action 'self'` intact. `require-trusted-types-for 'script'` is Report-Only, so a missing policy only reports. The change adds names to the allowlist, it does not loosen the enforced CSP (only the `worker-src` and host additions). Tests assert the strings.
2. **maps-key handling (client)**: key fetched lazily only when `EventMap` mounts, kept in React Query memory (`staleTime: Infinity`), not persisted to storage; `suppressErrorToast`, empty key means no map. Key is passed only to `APIProvider`. Server-side: endpoint is unauthenticated and rate limited (`5/minute`); exposure is by design, see F1. The "open in maps" link uses numeric lat/lng interpolated into a fixed `https://www.google.com/maps?q=` URL with `noopener noreferrer`.
3. **RequireAuth / RequireRole**: purely UX (client redirect `useReplace` to `/login` or `/clubs`, toast). Bypass by editing JS, disabling it, or reading the SSR shell is possible but yields nothing: the pages are static shells and every datum comes from the API. Verified in BE: mutations use `get_current_user`, organizer actions use `require_event_club_organizer`, reads use `get_optional_user` + `can_view_club` (`GET /events/{id}`). Role checks for `ALLOWED` are mirrored on the server, not trusted from the client. Only server gap found is F2. `RequireAuth` renders `children` only when `user` is set, so no flash of protected markup; `replace('/login')` is a constant path (no `returnUrl`, so no open redirect vector).
4. **XSS**: event title, description, address, city, venue name/address/description, book title/description are all rendered as React text nodes. No `dangerouslySetInnerHTML` in events code (only the nonce'd theme constant in the layout). Map marker `title` props are set through the Maps API as text. `event.coverUrl` goes to `<img src>` with `referrerPolicy="no-referrer"`; `javascript:` is inert in `img`, and CSP `img-src` blocks hosts outside the allowlist. No user-controlled `href` in events: links are internal `AppLink` paths built from UUIDs (`/clubs/${clubId}`, `/events/${id}`) or the fixed Google Maps URL. No user-supplied URL is rendered as an anchor.
5. **Open redirect**: events code has no `returnUrl`/`next`/`redirect` parameter handling; guard redirects are fixed paths; `app/page.tsx` redirects to constant `/events`. `AppLink` hrefs use server-provided UUIDs interpolated into same-origin paths (a malformed id would at worst yield a 404 path, not an external host since the path begins with `/`).
6. **RSVP / join mutations and CSRF**: requests are same-origin `/api/v1` with `credentials: include`, auth cookies are `SameSite=Lax` (POST/DELETE are not sent cross-site), and the BE `csrf_middleware` additionally requires an Origin/Referer in `ALLOWED_ORIGINS`/`CORS_ORIGIN_REGEX` for every non-safe method with an `access_token` cookie (missing header also rejected). `attend` is POST and cancel is DELETE, so no state change over GET. Ops requirement from R6 stands (Next origin in `ALLOWED_ORIGINS`). Join requests: same middleware; authorization is on the server. Rollback/refetch logic in a01d64b is client state only.
7. **Rendering of Google data**: the sanitizer/`dompurify-internal` and Maps `google-maps-api#html` TT names relate to library internals; no app code feeds user strings into `innerHTML`.

## Needs owner / BE decision

- F1: confirm the browser key has HTTP-referrer restrictions (prod + preview origins) and an API allowlist (Maps JavaScript API, optionally Places/Geocoding only if used from the browser), and that it differs from `MAPS_SERVER_API_KEY`. Set budget/quota alerts.
- F2: add `can_view_club` check to `attend_event_service` and `cancel_attendance` (404 for non-visible club).
- F3/F4: review collected TT/CSP reports, then tighten the allowlist before moving to enforcement.
