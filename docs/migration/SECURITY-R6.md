# Security review: R6 `/clubs/[id]` (feat/web-club-detail)

Scope: apps/web club detail, `/_internal/revalidate`, strangler manifest change, packages/api-client detail subset, new deps `qrcode` / `@types/qrcode`. Backend read for reference only (book-club-be 1d0d584).

## Findings

| # | Severity | Area | Finding | Status |
|---|---|---|---|---|
| F1 | Medium | Privacy (BE + FE) | `GET /clubs/{id}` and `GET /clubs/{id}/events` use `get_optional_user` and never check `is_public`. Any caller who knows a private club's UUID gets name, description, cover, address, lat/lng, member previews, events. The Next page renders this into server HTML and the 600 s data cache, and (before the fix) into title/og/twitter tags that link unfurlers read despite `noindex`. The API exposure pre-exists; R6 adds a second, crawlable/unfurlable channel. UUIDs are unguessable and private clubs are excluded from `GET /clubs`, so exposure needs the link. | FE mitigation fixed (metadata); **BE decision needed** |
| F2 | Low | Structured data | JSON-LD `image` used raw `coverUrl` (club and event) while og:image was scheme-checked. | Fixed: shared `safeHttpUrl` (http/https only) |
| F3 | Low | Revalidate | Body limit checked after `request.text()` fully buffered the body (char count, not bytes). | Fixed: `Content-Length` pre-check before reading; post-read check kept (auth happens first either way) |
| F4 | Info | Revalidate | Everything else OK, see below. | - |
| F5 | Info | Deps | `npm audit --omit=dev`: 0. `--audit-level=high` reports 13 dev-only highs (nx/axios/brace-expansion), none in `qrcode`. | No action |

## Checks

1. **`/_internal/revalidate`**: secret compared via `timingSafeEqual` on SHA-256 digests (equal length, constant time); 503 when `REVALIDATE_SECRET` unset (checked before auth); 401 before the body is read; tag allowlist is exactly `clubs` or `club:<uuid>` (anchored regex), max 20 tags, JSON only, 2 KiB cap; only `POST` exported (Next answers 405 for others); no CORS headers and a custom header means a cross-origin browser call needs a preflight that is never approved, so no browser CSRF; response is `private, no-store`; no logging anywhere. Not under `/api`, so the backend rewrite cannot reach it, and the proxy matcher excludes `_internal/` (no CSP/bucket cookie). Residual: no rate limit on secret guessing; the secret is 256-bit class if generated randomly, so acceptable (recommend `openssl rand -hex 32`, and Vercel WAF rate rule as defence in depth).
2. **Server fetches**: `serverApi` uses a null-token transport and its own `fetch` with no `credentials`, no cookie forwarding and no Authorization; 3 s timeout. `next.tags = club:<id>`. Cached data is whatever the backend returns to an anonymous caller (see F1). Personal data (membership, members list, my clubs) is fetched only client-side with cookies. `loadClub` validates UUID before any fetch and maps only 404/422 to `notFound()`.
3. **Private clubs (KEY QUESTION)**: confirmed real (see F1). Impact: link-holder-only disclosure, now also to crawlers that follow the link, link unfurlers (Slack/Telegram) and the shared ISR data cache; body HTML still carries name/description for a private club. **Recommendation (BE fix, preferred)**: in `get_club` and `list_club_events`, when `not club.is_public` and the caller is not a member/organizer/admin, return either 404 (hides existence; breaks invite-by-link join-request UX) or a stub (`id`, `name`, `isPublic:false`, `memberCount`; no description, cover, address, lat/lng, previews, events). Stub is the better product fit because the join-request flow needs a name. The Next page then needs no change: its anonymous cached answer is automatically the stub, and signed-in members would get full data via a client refetch (follow-up in R6.1, since today the page only refetches events). **FE safe default implemented**: for `isPublic=false`, `generateMetadata` returns generic title/description/image (no club text) with `index:false`; JSON-LD already skipped. Not done on FE: redacting the body, since it would need a client-side club fetch for Hero/About and gives no real protection while the API stays open. Owner decision needed: stub vs 404 on BE.
4. **Rendering**: club/event/member text is rendered as React text. The only `dangerouslySetInnerHTML` are the JSON-LD component (escapes `<`, `>`, `&`, U+2028, U+2029; round-trips) and the nonce'd theme script constant in the layout. Cover `<img>` uses `referrerPolicy=no-referrer`; `javascript:`/`data:` in `src` is inert and CSP `img-src` restricts hosts. Book-store links: `https://` only, `target=_blank rel="noopener noreferrer"`. Organizer social links use fixed https bases. og:image validated http(s) (`safeHttpUrl`, now shared).
5. **CSP / Trusted Types**: page goes through the proxy handler: per-request nonce, `strict-dynamic`; lazy chunks (`qrcode`, api-client) load through the runtime with the nonce inherited. `qrcode.toCanvas` draws on a canvas (no innerHTML/SVG string sinks), so Report-Only TT produces no new violations from it. Enforcement still deferred; keep report-only. Functional note: cover images from hosts outside `img-src` (openlibrary, supabase, maps) are blocked by CSP; tracking as a product/CSP question, not a vulnerability.
6. **Mutations**: api-client `cookieTransport` uses same-origin `/api/v1` with `credentials: include`; backend CSRF middleware requires a matching Origin/Referer for cookie-authenticated non-GET requests (browsers send Origin on same-origin POST). Ops requirement: the web origin must be in `ALLOWED_ORIGINS`/`CORS_ORIGIN_REGEX` for the Next deployment. No tokens in JS storage: localStorage/document.cookie only hold theme/locale and the analytics bucket.
7. **Strangler**: `:id` compiles to an anchored UUID regex; `/clubs/create` and non-UUID single segments are `isLegacyShadowed` and go to legacy (tests cover it). Proxy matcher additionally excludes `_internal/`. Legacy rewrite target keeps the original host (`legacyOrigin` only), path taken from `nextUrl.pathname` with leading `//` collapsed, so no open redirect (rewrite, not redirect) and no host override; `..` segments are normalised by URL parsing before matching.
8. **Deps**: lock diff adds only the `apps/web` workspace entries; `node_modules/qrcode@1.5.4` and `@types/qrcode@1.5.6` entries already existed with integrity hashes. `npm ci --dry-run` succeeds (lock consistent with package.json).

## Needs owner / BE decision

- F1: backend policy for private clubs to anonymous/non-member callers (stub recommended), plus R6.1 client refetch for members.
- Set `REVALIDATE_SECRET` in Vercel only together with the BE notifier; add `ALLOWED_ORIGINS` entry for the Next origin.
